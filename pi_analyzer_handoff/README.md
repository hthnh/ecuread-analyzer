# EcuRead Pi Analyzer Inference Handoff

This bundle is a minimal inference handoff exported from the current DriveSafe Analyzer checkout. It accepts `canonical-telemetry-v2`, validates the required V2 signals, creates 50/10 sample windows, extracts the `ecu-window-features-v1` 81-feature frame, runs the production IsolationForest model, and returns `limited_data`, `ok`, `monitor`, or `attention` session status.

## Source Revision

`unavailable-no-git-repository`

The source checkout used for export did not contain a `.git` directory when the revision is `unavailable-no-git-repository`.

## Production Model

- Model directory: `models/honda_keihin_71_17_v2/`
- Model version: `iforest-baseline-20260920T091709Z`
- Telemetry schema: `canonical-telemetry-v2`
- Feature schema: `ecu-window-features-v1`
- Decoder provenance: `honda_keihin_71_17:1.0.0`
- Feature count: `81`
- Signal columns: `rpm, tps_voltage, tps_raw, battery_voltage, iat_c, ect_c`

## Exported Source

- `app/domain/telemetry.py`: canonical telemetry session and sample models, schema constants, required signal lookup.
- `app/domain/model.py`: feature schema constant used by validation and inference.
- `app/config.py`: inference windowing and evidence-gate settings defaults.
- `app/ml/validation.py`: canonical ML input validation.
- `app/ml/windowing.py`: 50/10 window construction.
- `app/ml/features.py`: deterministic 81-feature extraction for V2 signal columns.
- `app/ml/inference.py`: model loading, feature schema checks, sklearn inference, anomaly/status output.
- `app/ml/scoring.py`: health score and unusual feature ranking.
- `app/ml/training.py`: dependency-safe artifact path shim only; no training API is included.
- `app/services/pi_analysis.py`: small persistence-free extraction of the audited `AnalysisService` call order and summary construction.
- Package `__init__.py` files: import support for the minimal source tree.

## Golden Fixtures

- `fixtures/v2_short_or_limited.json`: derived from `data/telemetry/ride-20260901-0715`, trimmed to canonical V2 inference fields, produces 7 windows.
- `fixtures/v2_regular_session.json`: derived from `data/telemetry/ride-20260904-1623`, trimmed to canonical V2 inference fields, produces 297 windows.

Device identifiers are omitted from fixtures. No raw ingestion records, credentials, or cloud/server configuration are included.

## Golden Outputs

The golden outputs were generated by running the current Analyzer `AnalysisService(..., persist=False)` against the exact fixture payloads and production model artifacts copied into this bundle.

- `golden/v2_short_or_limited.analysis.json`: stable limited-data summary.
- `golden/v2_regular_session.analysis.json`: stable regular-session summary.
- `golden/v2_regular_session.features.csv`: deterministic regular-session feature frame, including all 81 model features.
- `golden/v2_regular_session.windows.csv`: deterministic regular-session scored windows, including predictions and anomaly flags.

Random identifiers such as `analysis_run_id` are excluded from strict parity artifacts.

## Numeric Tolerance

Use exact equality for window counts, feature names, predictions, `is_anomaly`, model/schema IDs, and status. Use `atol=1e-9` and `rtol=1e-12` for floating-point feature, score, and health values. The tolerance is tight enough to catch material pipeline drift while allowing CSV round-trip representation noise.

## Verification

From the repository root:

```bash
.venv/bin/python scripts/verify_pi_analyzer_handoff.py --bundle pi_analyzer_handoff
```

From inside the unpacked bundle:

```bash
python scripts/verify_pi_analyzer_handoff.py
```

The verifier checks `MANIFEST.sha256`, model metadata, sklearn artifact loading, 81 feature names, limited-data evidence behavior, regular-session feature parity, anomaly decisions, and final summaries.

## Deliberately Excluded

- RAW ingestion and native Honda decoder modules (`app/ingestion/*`, `app/ecu/*`).
- DriveSafe repositories, session storage, analysis filesystem persistence, API routers, FastAPI app, cloud/web code.
- Training APIs, retraining scripts, training datasets, and the human-normal candidate model.
- Full historical analysis/results/raw data directories.
